# 0008: Anonymous public test board (no accounts)

**Status:** accepted · 2026-10-25 · supersedes 0001 (auth), 0007, and the auth parts of 0003 and 0005 on `main`. The account version is kept at tag `v1-with-auth`.

**Context:** The deployed demo is a free Vercel + Neon app with no outbound mail provider, so email verification and new-chirp emails could not work in production (the tag already had to switch verification off with `CHIRPER_REQUIRE_VERIFIED=false`). Making strangers register before they can try a public demo adds friction and means we hold their email addresses, when we only want them to post a test message.

**Decision:**
- **No accounts.** Fortify, the starter kit's auth and settings pages, passkeys and 2FA are removed. Anyone can post, and every chirp shows as "Anonymous".
- **Ownership is a browser token.** On the first post, `AuthorToken` creates `Str::random(40)` and stores it in the `chirper_author` cookie. The cookie is http-only and encrypted by Laravel's `EncryptCookies` middleware, and it lasts `chirper.author_cookie_days` (7), which is longer than a chirp lives. Chirps store only `author_token_hash`, the SHA-256 of the token (64 chars, indexed, `#[Hidden]`, not fillable). `ChirpPolicy::update`/`delete` call `AuthorToken::owns()`, which uses `hash_equals`. A token that isn't exactly 40 chars, or a cookie the app didn't encrypt, counts as no token. A database leak can't forge ownership, because the hash is not the token and the cookie can't be forged without `APP_KEY`. The cost: clearing cookies or switching browsers loses edit and delete rights. That's acceptable for a 24-hour board.
- **PII guard.** `NoPersonalData` rejects text that looks like an email address or a 9+ digit number (phone or card numbers, allowing spaces, dots, dashes, brackets and a leading `+`). It runs on both create and update. It is best effort and backs up the disclaimer banner shown on every page. It can't catch names or addresses.
- **Abuse limits per IP.** The `chirps` limiter allows 5 posts a minute and 50 a day per `$request->ip()`. Without accounts there is nothing else to key on. This relies on `bootstrap/app.php` trusting `X-Forwarded-For` from Vercel's proxy. A hidden `website` honeypot field makes bot posts look successful while saving nothing.
- **24-hour expiry with no cron.** `Chirp::live()` hides chirps older than `chirper.lifetime_hours` (24) from the timeline. Route binding uses the same scope, so edit, update and delete return 404 on an expired chirp. `store` runs `Chirp::pruneExpired()` before each insert. We don't need a scheduler, which matters because Vercel Hobby crons run only once a day.
- **Migration** `2026_10_25_000000_make_chirps_anonymous` deletes every existing chirp (their owners' accounts are gone), replaces `user_id` with `author_token_hash`, and drops `sent_chirp_notifications`, `passkeys` and the 2FA columns if they exist.
- **Notifications dropped.** With no accounts there is nobody to email, so `ChirpCreated`, the listener, `NewChirp` and the ledger are removed.

**Consequences:** The demo is zero-friction and holds no personal data by design. Ownership is weaker than an account: it is per browser, can't be recovered, and a leaked cookie gives edit rights until it expires. The per-IP limit is only as trustworthy as the proxy header, so a host that doesn't overwrite `X-Forwarded-For` would let clients choose their own bucket. Expired rows stay in the table, hidden, until the next post. Tests: `tests/Feature/Board/`.
